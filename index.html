ETAPA 1 DE 10

Modelagem do Banco de Dados

O Papyro é um sistema computacional de gerenciamento de uma biblioteca escolar, construído como uma API REST (Representational State Transfer) em Node JS, com o Express e o banco de dados MySQL. Antes do código, vamos entender quais dados a biblioteca escolar guarda e como eles se relacionam.

Passo a Passo

Passo 1 - Crie a pasta do projeto

Abra o VS Code e crie uma pasta vazia chamada de Papyro em Node JS, onde ficarão todos os arquivos do projeto.

Abrindo a pasta no VS Code Clique em Arquivo → Abrir Pasta e selecione a pasta do projeto, para que o terminal do VS Code já abra nela.

Passo 2 - Conheça as entidades do sistema computacional

O banco de dados do Papyro tem quatro tabelas:

  • livro guarda os dados da obra, como o ISBN (International Standard Book Number), o título e o autor.
  • exemplar é cada cópia física de um livro, identificada pelo número de tombo (codigo) e pela situação (disponível, emprestado ou extraviado).
  • leitor guarda os dados de quem pega livros emprestados, como a matrícula, o CPF (Cadastro de Pessoas Físicas), o nome e o tipo (aluno ou professor).
  • emprestimo registra qual leitor pegou qual exemplar, com as datas do empréstimo, da devolução prevista e da devolução real.

Passo 4 - Compreender o modelo de dados

  • Toda tabela tem uma coluna id como PK (Primary Key), a chave primária, que é gerada automaticamente e identifica cada registro.
  • Os campos que identificam o registro no mundo real, como o isbn, o codigo e a matricula, não são chaves primárias, mas também não podem se repetir.
  • As colunas FK (Foreign Key), as chaves estrangeiras, guardam o id de um registro de outra tabela, como o livro de cada exemplar.
  • Separar o livro do exemplar permite ter várias cópias do mesmo título e saber qual cópia está com qual leitor.
  • No pé de galinha, o traço duplo é o lado "um" e as três pontas são o lado "muitos". Um livro tem muitos exemplares, e cada exemplar e cada leitor têm muitos empréstimos.

ETAPA 2 DE 10

Construção do Banco de Dados

Agora vamos transformar o DER em tabelas reais no MySQL, com um arquivo SQL (Structured Query Language).

Passo a Passo

Passo 1 - Crie o arquivo do banco de dados

Na raiz da pasta do projeto, crie o arquivo Schema (Papyro).sql com o conteúdo abaixo:

sql — Schema (Papyro).sql
-- Cria a base de dados.
DROP DATABASE IF EXISTS papyro_db;
CREATE DATABASE IF NOT EXISTS papyro_db;

-- Define o uso da base de dados.
USE papyro_db;

-- Cria a tabela de livro.
CREATE TABLE IF NOT EXISTS livro (
    id INT AUTO_INCREMENT PRIMARY KEY,
    isbn VARCHAR(13) NOT NULL UNIQUE,
    titulo VARCHAR(150) NOT NULL,
    autor VARCHAR(100) NOT NULL,
    editora VARCHAR(100) NOT NULL,
    ano_publicacao INT NOT NULL,
    edicao VARCHAR(20) NOT NULL,
    genero VARCHAR(50) NOT NULL
);

-- Cria a tabela de exemplar.
CREATE TABLE IF NOT EXISTS exemplar (
    id INT AUTO_INCREMENT PRIMARY KEY,
    id_livro INT NOT NULL,
    codigo INT NOT NULL UNIQUE,
    situacao ENUM('Disponivel', 'Emprestado', 'Extraviado')
    NOT NULL DEFAULT 'Disponivel',

    -- Definição da chave estrangeira.
    FOREIGN KEY (id_livro) REFERENCES livro(id)
);

-- Cria a tabela de leitor.
CREATE TABLE IF NOT EXISTS leitor (
    id INT AUTO_INCREMENT PRIMARY KEY,
    matricula VARCHAR(20) NOT NULL UNIQUE,
    cpf VARCHAR(14) UNIQUE,
    nome VARCHAR(100) NOT NULL,
    tipo ENUM('Aluno', 'Professor') NOT NULL,
    turma VARCHAR(20),
    telefone VARCHAR(20) NOT NULL,
    email VARCHAR(100) NOT NULL
);

-- Cria a tabela de empréstimo.
CREATE TABLE IF NOT EXISTS emprestimo (
    id INT AUTO_INCREMENT PRIMARY KEY,
    id_leitor INT NOT NULL,
    id_exemplar INT NOT NULL,
    data_emprestimo DATE NOT NULL,
    data_prevista_devolucao DATE NOT NULL,
    data_devolucao DATE NULL,
    
    -- Definição das chaves estrangeiras.
    FOREIGN KEY (id_leitor) REFERENCES leitor(id),
    FOREIGN KEY (id_exemplar) REFERENCES exemplar(id)
);

Passo 2 - Execute o arquivo no MySQL Workbench

Abra o MySQL Workbench, conecte-se ao servidor local, cole o conteúdo do Schema (Papyro).sql em uma nova aba de consulta e clique no ícone do raio para executar todo o conteúdo.

Atenção ao DROP DATABASE A primeira instrução apaga o banco de dados papyro_db, se ele existir. Executar o arquivo de novo apaga todos os dados cadastrados.

Passo 3 - Compreender as tabelas criadas

  • AUTO_INCREMENT faz o MySQL gerar automaticamente o id de cada novo registro.
  • UNIQUE impede valores repetidos nas colunas isbn, codigo, matricula e cpf.
  • NOT NULL torna a coluna obrigatória. O cpf e a turma do leitor ficam opcionais, pois nem todo aluno tem CPF e o professor não tem turma.
  • ENUM limita a coluna a uma lista fixa de valores, e o DEFAULT 'Disponivel' faz todo novo exemplar começar como disponível.
  • data_devolucao aceita o valor nulo (NULL), que indica um exemplar ainda não devolvido.
  • FOREIGN KEY ... REFERENCES cria a chave estrangeira e impede, por exemplo, o cadastro de um exemplar de um livro que não existe. Por isso, a tabela referenciada é sempre criada antes da tabela que aponta para ela.

Construção do Backend

O navegador da web não se conecta direto ao banco de dados. Essa ponte é o backend, que vamos construir em linguagem de programação JavaScript, com o Node JS e o Express. Nesta etapa, vamos preparar apenas o servidor da web, ainda sem o banco de dados.

Passo a Passo

Passo 1 - Verifique a instalação do Node JS

Abra o terminal do VS Code na pasta do projeto e execute os comandos abaixo, um de cada vez:

bash
node -v
npm -v
Sobre o Node JS e o npm O Node JS executa o JavaScript fora do navegador da web, e o npm (Node Package Manager) instala as bibliotecas. Cada comando deve exibir um número de versão. Se o comando não for reconhecido, o Node JS não está instalado.

Passo 2 - Inicie o projeto Node JS

No terminal do VS Code, execute o comando abaixo:

bash

Esse comando cria o arquivo package.json, com um conteúdo parecido com o abaixo:

Sobre o npm init O npm init transforma a pasta em um projeto Node JS, e o -y aceita as respostas padrão. O conteúdo do package.json pode variar um pouco conforme a versão do npm.

Passo 3 - Instale o Express

No terminal do VS Code, execute o comando abaixo:

bash

Sobre o npm install O npm baixa o Express para a pasta node_modules, registra o Express no package.json e cria o package-lock.json, com as versões exatas instaladas. A pasta node_modules e o package-lock.json nunca devem ser editados à mão.

Passo 4 - Crie o arquivo de backend

Na raiz da pasta do projeto, crie o arquivo app.js com o conteúdo abaixo:

javascript — app.js
// Importa o Express - Framework para Servidor da Web.
const express = require("express");

// Cria a aplicação da web.
const app = express();

// Permite que o Express entenda requisições em formato de JSON.
app.use(express.json());

// Define a porta onde o servidor da web irá trabalhar.
const porta = 3000;

// Cria uma rota que responde na raiz da web com um texto.
app.get("/", (req, res) => {

  // Envia uma mensagem de boas-vindas ao navegador.
  res.send("Servidor de backend da Papyro no ar!");
});

// Sobe o servidor da web e o mantém funcionando na porta definida.
app.listen(porta, () => {

  // Avisa no terminal que o servidor da web está funcionando.
  console.log(`Servidor da web rodando em http://localhost:${porta}`);
});

Passo 5 - Compreender a estrutura do backend

  • package.json descreve o projeto, e a chave dependencies lista as bibliotecas instaladas.
  • require("express") importa o Express, o framework do servidor da web, e express() cria a aplicação da web.
  • express.json() permite ler os dados enviados em JSON (JavaScript Object Notation), o formato de todas as rotas da API.
  • app.get("/", ...) cria uma rota GET na raiz da web. O req traz os dados da requisição, e o res envia a resposta.
  • app.listen(porta, ...) sobe o servidor da web na porta 3000 e o mantém aguardando as requisições.

Conexão com o Banco de Dados

Agora vamos preparar a conexão do backend com o MySQL. Os dados de acesso ao banco de dados ficam em um arquivo de variáveis de ambiente, separados do código.

Passo a Passo

Passo 1 - Instale as bibliotecas de conexão

Pare o servidor da web com as teclas Ctrl + C e, no terminal do VS Code, execute o comando abaixo:

bash
npm install dotenv mysql2

Esse comando instala duas bibliotecas:

  • dotenv lê o arquivo de variáveis de ambiente (.env).
  • mysql2 conecta o Node JS ao MySQL e executa as instruções de SQL.

Passo 2 - Crie o arquivo de variáveis de ambiente

Na raiz da pasta do projeto, crie o arquivo .env com o conteúdo abaixo. Se a senha do seu MySQL não for root, altere o valor de DB_PASSWORD:

# Usuário do banco de dados MySQL.

# Senha do usuário do banco de dados MySQL.
DB_PASSWORD=root

# Nome da base de dados.
DB_NAME=papyro_db
Atenção O arquivo .env nunca deve ser enviado para o GitHub, pois ele contém senhas e chaves de acesso.

Passo 3 - Crie o arquivo de conexão com o banco de dados

Na raiz da pasta do projeto, crie o arquivo database.js com o conteúdo abaixo:

javascript — database.js
// Importa o Dotenv para leitura das variáveis de ambiente.
require("dotenv").config();

// Importa o MySQL2 para conexão com o banco de dados.
const mysql = require("mysql2/promise");

// Cria um conjunto de conexões com o banco de dados.
const conexao = mysql.createPool({
  host: process.env.DB_HOST,
  port: process.env.DB_PORT,
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME
});

// Exporta a conexão para que os outros arquivos possam utilizá-la.
module.exports = conexao;

Passo 4 - Compreender a conexão com o banco de dados

  • require("dotenv").config() lê o .env, e cada valor passa a ser recuperado com process.env, como em process.env.DB_HOST.
  • mysql2/promise é a versão da biblioteca MySQL2 que permite usar async e await nas consultas ao banco de dados.
  • mysql.createPool() cria um conjunto de conexões reaproveitadas entre as requisições, em vez de abrir uma conexão nova a cada requisição.
  • module.exports exporta a conexao, que é criada em um único lugar e usada por todas as rotas da API.
  • Com o .env, cada computador usa a própria senha do MySQL sem alterar o código.

ETAPA 6 DE 10

Estrutura do Backend em Camadas

Com quatro tabelas e várias rotas da API, o app.js ficaria grande e difícil de manter. Por isso, o backend do Papyro será organizado em camadas, inspiradas no padrão MVC (Model-View-Controller), em que cada pasta tem uma única responsabilidade.

Passo a Passo

Passo 1 - Crie as pastas das camadas

Na raiz da pasta do projeto, crie a pasta routes, para as rotas da API, e a pasta controllers, para as funções que executam cada rota.

Passo 2 - Compreender a responsabilidade de cada camada

  • app.js inicia o servidor da web e liga cada grupo de rotas ao seu endereço, como /livros.
  • routes define qual método HTTP (HyperText Transfer Protocol) e qual endereço chamam qual função do controller, sem acessar o banco de dados.
  • controllers recebe a requisição, valida os dados, executa o SQL pela conexao e devolve a resposta em JSON com o código de status.
  • database.js continua sendo o único lugar onde a conexão com o banco de dados é criada.
Por que não existe a camada de views? Em uma API REST, o backend devolve apenas dados em JSON, e quem desenha as telas é o frontend. Por isso, o Papyro usa somente as rotas e os controllers, com o SQL dentro dos próprios controllers.

Passo 3 - Compreender o caminho de uma requisição

Uma requisição, como a lista de livros, percorre as camadas nesta ordem:

GET/livros
1
Servidor da web app.js Liga o endereço /livros às rotas de livro.
2
Rotas routes/bookRoutes.js Descobre qual função atende o método GET.
3
Controller controllers/bookController.js Executa o SQL e monta a resposta.
4
Banco de dados database.js → MySQL Busca os dados na tabela livro.

Passo 4 - Conheça a convenção de nomes dos arquivos

Cada tabela vai ganhar um arquivo de rotas e um arquivo de controller, com o nome da tabela em inglês no início (o exemplar é chamado de item):

  • livro → routes/bookRoutes.js e controllers/bookController.js
  • exemplar → routes/itemRoutes.js e controllers/itemController.js
  • leitor → routes/readerRoutes.js e controllers/readerController.js
  • emprestimo → routes/loanRoutes.js e controllers/loanController.js

Esses arquivos serão criados nas próximas etapas.

Cadastro de Livro

Passo 2 - Crie o controller de livro

Na pasta controllers, crie o arquivo bookController.js com o conteúdo abaixo:

javascript — controllers/bookController.js
// Importa a conexão com o banco de dados.
const conexao = require("../database");

// Cadastra um novo livro.
async function cadastrar(req, res) {

  // Recebe os dados enviados na requisição.
  const { isbn, titulo, autor, editora, ano_publicacao, edicao, genero } = req.body;

  // Verifica se todos os campos obrigatórios foram enviados.
  if (!isbn || !titulo || !autor || !editora || !ano_publicacao || !edicao || !genero) {

    // Responde com o status 400 (requisição inválida) e uma mensagem de erro.
    return res.status(400).json({ erro: "Preencha todos os campos obrigatórios..." });
  }

  try {

    // Verifica se o ISBN já está cadastrado.
    const [livros] = await conexao.query("SELECT id FROM livro WHERE isbn = ?", [isbn]);

    if (livros.length > 0) {

      // Responde com o status 409 (conflito) e uma mensagem de erro.

const conexao = require("../database");

// Cadastra um novo leitor.
async function cadastrar(req, res) {

  // Recebe os dados enviados na requisição.
  const { matricula, cpf, nome, tipo, turma, telefone, email } = req.body;

  // Verifica se todos os campos obrigatórios foram enviados.
  if (!matricula || !nome || !tipo || !telefone || !email) {

    // Responde com o status 400 (requisição inválida) e uma mensagem de erro.

  }

  // Verifica se o tipo de leitor é um dos valores aceitos pelo banco de dados.
  if (tipo !== "Aluno" && tipo !== "Professor") {

    // Responde com o status 400 (requisição inválida) e uma mensagem de erro.

  }

  try {

    // Verifica se a matrícula ou o CPF já estão cadastrados.
    const [leitores] = await conexao.query(
      "SELECT id FROM leitor WHERE matricula = ? OR cpf = ?",

    );

    if (leitores.length > 0) {

    // Executa o SQL para cadastrar o leitor.
    await conexao.query(
      "INSERT INTO leitor (matricula, cpf, nome, tipo, turma, telefone, email) VALUES (?, ?, ?, ?, ?, ?, ?)",
      [matricula, cpf || null, nome, tipo, turma || null, telefone, email]
    );

    // Responde com o status 201 (criado) e uma mensagem de sucesso.

javascript — controllers/loanController.js
// Importa a conexão com o banco de dados.
const conexao = require("../database");

// Verifica se uma data está no formato AAAA-MM-DD e existe no calendário.
function validarData(data) {

  // Converte o texto recebido em uma data do JavaScript.
  const dataConvertida = new Date(data);

  // A data é válida quando segue o formato, pode ser convertida e não muda após a conversão.
  return /^\d{4}-\d{2}-\d{2}$/.test(data) &&
    !isNaN(dataConvertida) &&
    dataConvertida.toISOString().slice(0, 10) === data;
}

// Cadastra um novo empréstimo.
async function cadastrar(req, res) {

  // Recebe os dados enviados na requisição.
  const { id_leitor, id_exemplar, data_emprestimo, data_prevista_devolucao } = req.body;

  // Verifica se todos os campos obrigatórios foram enviados.
  if (!id_leitor || !id_exemplar || !data_emprestimo || !data_prevista_devolucao) {

    // Responde com o status 400 (requisição inválida) e uma mensagem de erro.
    return res.status(400).json({ erro: "Preencha todos os campos obrigatórios..." });
  }

  // Verifica se as duas datas são válidas.
  if (!validarData(data_emprestimo) || !validarData(data_prevista_devolucao)) {

    // Responde com o status 400 (requisição inválida) e uma mensagem de erro.
    return res.status(400).json({ erro: "Informe as datas no formato AAAA-MM-DD..." });
  }

  // Verifica se a data prevista de devolução é posterior à data do empréstimo.
  if (data_prevista_devolucao <= data_emprestimo) {

    // Responde com o status 400 (requisição inválida) e uma mensagem de erro.
    return res.status(400).json({ erro: "A data prevista de devolução deve ser posterior à data do empréstimo..." });
  }

  try {

    // Verifica se o leitor informado existe.
    const [leitores] = await conexao.query("SELECT id FROM leitor WHERE id = ?", [id_leitor]);

    if (leitores.length === 0) {

      // Responde com o status 404 (não encontrado) e uma mensagem de erro.
      return res.status(404).json({ erro: "Leitor não encontrado..." });
    }

    // Busca o exemplar informado para conferir a situação dele.
    const [exemplares] = await conexao.query("SELECT situacao FROM exemplar WHERE id = ?", [id_exemplar]);

    if (exemplares.length === 0) {

      // Responde com o status 404 (não encontrado) e uma mensagem de erro.
      return res.status(404).json({ erro: "Exemplar não encontrado..." });
    }

    // Verifica se o exemplar está disponível para empréstimo.
    if (exemplares[0].situacao !== "Disponivel") {

      // Responde com o status 409 (conflito) e uma mensagem de erro.
      return res.status(409).json({ erro: "Exemplar não está disponível para empréstimo..." });
    }

    // Executa o SQL para cadastrar o empréstimo.
    await conexao.query(
      "INSERT INTO emprestimo (id_leitor, id_exemplar, data_emprestimo, data_prevista_devolucao) VALUES (?, ?, ?, ?)",
      [id_leitor, id_exemplar, data_emprestimo, data_prevista_devolucao]
    );

    // Executa o SQL para mudar a situação do exemplar para Emprestado.
    await conexao.query("UPDATE exemplar SET situacao = 'Emprestado' WHERE id = ?", [id_exemplar]);

    // Responde com o status 201 (criado) e uma mensagem de sucesso.
    res.status(201).json({ mensagem: "Empréstimo cadastrado com sucesso!" });

  } catch (erro) {

    // Mostra no terminal o erro, para o programador.
    console.log("Erro ao cadastrar o empréstimo: " + erro.message);

    // Responde com o status 500 (erro no servidor da web) e uma mensagem genérica.
    res.status(500).json({ erro: "Não foi possível atender sua requisição..." });
  }
}

Rotas de Exclusão (DELETE)

Agora vamos criar a exclusão de registros com o método DELETE, a última operação da API REST. Desta vez, a ordem é a inversa das chaves estrangeiras, começando pelo empréstimo, pois um registro só pode ser excluído quando nenhum outro registro depende dele.

Sobre o método DELETE O DELETE apaga um registro indicado pelo id na URL, como /emprestimos/3, e não envia nada na aba Body. A exclusão não pode ser desfeita, por isso o controller confere antes se o registro existe e se nenhum outro registro depende dele.

// Exclui um empréstimo, de acordo com o id informado na URL.
async function excluir(req, res) {

  // Recebe o id informado na URL.
  const { id } = req.params;

  try {

    // Busca o empréstimo informado para conferir o exemplar e a devolução dele.
    const [emprestimos] = await conexao.query("SELECT id_exemplar, data_devolucao FROM emprestimo WHERE id = ?", [id]);

    if (emprestimos.length === 0) {

      // Responde com o status 404 (não encontrado) e uma mensagem de erro.
      return res.status(404).json({ erro: "Empréstimo não encontrado..." });
    }

    // Executa o SQL para excluir o empréstimo.
    await conexao.query("DELETE FROM emprestimo WHERE id = ?", [id]);

    // Verifica se o empréstimo ainda não tinha sido devolvido.
    if (emprestimos[0].data_devolucao === null) {

      // Executa o SQL para mudar a situação do exemplar para Disponivel.
      await conexao.query("UPDATE exemplar SET situacao = 'Disponivel' WHERE id = ?", [emprestimos[0].id_exemplar]);
    }

    // Responde com o status 200 (sucesso) e uma mensagem de sucesso.
    res.status(200).json({ mensagem: "Empréstimo excluído com sucesso!" });

  } catch (erro) {

    // Mostra no terminal o erro, para o programador.
    console.log("Erro ao excluir o empréstimo: " + erro.message);

    // Responde com o status 500 (erro no servidor da web) e uma mensagem genérica.
